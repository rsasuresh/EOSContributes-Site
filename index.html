What's inside

Everything an embedded product needs, layered.

Pick a product profile at configure time and build only what that device uses.

RTOS kernel

Tasks, synchronisation primitives, IPC and multicore support in eos_kernel.

Hardware abstraction

A platform-split HAL with a Linux host backend and a bare-metal RTOS backend.

Driver framework

Drivers plus a devicetree parser, so board wiring lives in data, not code.

Crypto & security

AES, SHA-256 and SHA-512 pass NIST vectors. RSA/ECC verification is planned.

Runtime services

OTA, filesystem, sensor, motor, GPS, UI, init and more under services/.

Debug & simulation

GDB stub, core dumps, a simulator, and unit, functional, fuzz and performance tests.

Architecture

Layers you can reason about.

Your application sits on services and the kernel; the HAL is the only layer that knows which silicon it runs on. Swap the backend, keep the code.

  • EOS_PLATFORM=linux|rtos selects the HAL backend
  • EOS_PRODUCT selects one of 48 profiles
  • Toolchain files for Cortex-M4 and Cortex-R5 exercised on every release

Quick start

Build it in under a minute.

Requires CMake ≥ 3.16 and a C11 compiler (GCC, Clang, or MSVC on Windows).

git clone https://github.com/embeddedos-org/eos.git
cd eos
cmake -B build/host -DCMAKE_BUILD_TYPE=Release
cmake --build build/host --parallel
cmake -B build/host -DEOS_BUILD_TESTS=ON -DEOS_PRODUCT=vbox_test
cmake --build build/host --parallel
ctest --test-dir build/host --output-on-failure
cmake -B build/arm -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=toolchains/arm-cortex-m4.cmake \
  -DEOS_BUILD_TESTS=OFF
cmake --build build/arm --parallel
